# 分钱机制诊断

一个纯前端工具，零后端、零构建、零依赖（除 CDN）。

**L1（免费）** 做体检：从现象出发，判断你的分钱机制最可能是哪里出了问题。
**L2（¥199）** 给方案：接下来改什么、按什么顺序、什么条件算改对了。

边界写在产品里，也写在这里：

- 只做现金激励。股权、期权的具体条款涉及法律和财税，不碰。
- **不给比例数字。** 比例没有普适解，要由用户用自己的业务数据推出来。
- 输出是**待确认的假设**，不是结论。
- 一次只拧一个旋钮。同时动五个，三个月后分不清是哪个起了作用。

## 要改哪里

**`js/pay-data.js`** —— 规则库。改完刷新页面就生效，不需要构建。

里面装着：29 条病因（22 根因 + 7 衍生）、109 条症状、5 个旋钮、18 个改法、
6 条通用判断、两个前置问的影响表、6 档验证时间窗。

**`l2/js/l2-data.js`** —— L2 的方案内容。**18 篇手册现在是空的**，
每篇按六段写：这一条在说什么 / 怎么判断该不该动它 / 具体怎么改 /
什么条件算成功 / 什么条件下算改错了怎么退回来 / 最容易踩的坑。

**`待填清单.md`** —— 规则库里需要人工判断的内容全在这里，每条下面留了
「改成：」那一行。改完代码重跑一次就同步。

## 改完要跑

```bash
node tools/selfcheck.js     # 规则库自检
node tools/export-review.js # 重新导出待填清单
```

**自检专防「静默失败」**——这类错误不报错，只是答案慢慢变得不对：

- 孤儿病因（没有任何症状指向它 → 永远诊断不出来）
- 症状指向了不存在的病因
- 病因的 knob 值写错（写错的话「调整的思路」整块不渲染，页面上看不出来）
- 改法没登记、或指向不存在的改法
- 前置问的某个选项没登记影响（选了等于没选）
- 话术卡里出现「你/你们」（那是指控，不是证据句）

自检可以直接传路径，用来测它自己：

```bash
node tools/selfcheck.js 某个改坏了的文件.js
```

浏览器里也有一份同样的检查（`validateRulebook()`），页面加载时跑，
有问题在 console 报错——因为改 `pay-data.js` 是直接刷新的，不会每次都去跑 node。

## 部署

纯静态，丢到任意静态托管即可（GitHub Pages / Cloudflare Pages）。

**统计**：ID 在 `js/analytics.js` 顶部，**改一处，五个页面一起生效**。
留空就不上报（页面照常跑）。这个 ID 要单独给这个工具用，不要跟战略诊断那个混。

**收款码**：在 `images/wechat-pay-199.jpg`。换的话直接替换这个文件。

**上线前唯一还要确认的**：`l2/js/l2-data.js` 里的 18 篇手册。现在是空的，
方案页会显示成「这一篇还没写」，并列出该写的六段。
